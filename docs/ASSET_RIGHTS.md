# Asset rights register

Who owns what on this site, and on what terms. Written because the
pre-release audit found two published photographs with blank credit fields
and no record anywhere of where they came from — and because a campaign site
that quotes its sources for every fare and every departure count should hold
itself to the same standard for its pictures.

**Nothing in this file is guessed.** Where the answer is not known it says so.

## Original to this project

| Asset | What it is | Notes |
|---|---|---|
| `brand/mark-source.png` | The circular pier/pavilion mark | Supplied by the site owner. Every derived size (`brand/mark-*.png`, `favicon-*.png`, `apple-touch-icon.png`, `favicon.ico`) is generated from it by `scripts/prepare_brand_mark.py` and can be rebuilt at any time. |
| `icons/*.png` | Operator bus illustrations | Generated by `scripts/build_icons.py` from the masters in `icons/source/`. |
| `style.css`, `app.js`, `api/`, `scripts/`, `worker/` | All code | Written for this project. |
| `data/*.json` | Curated datasets | Compiled for this project. Individual figures cite their own sources; `data/boundary_evidence.json` is generated and carries its method. |

## Unresolved — needs the owner's decision

| Asset | Question |
|---|---|
| `media/updates/fare-cap-2-pounds.jpg` | Where did this photograph come from, and on what terms? The `credit` field is empty and marked `credit_status: "unconfirmed"` in `data/updates.json`. |
| `media/updates/ticketer-contactless.jpg` | The same question. |
| Project licence | There is no `LICENSE` file, and the README describes the project as open source. Choosing a licence is the owner's decision, not one to make on their behalf — but the two statements should not both stand. |

Operator liveries and route colours are used to identify services, which is
descriptive use, not a claim of endorsement. The site says in its About page
that it is independent of every operator and council named on it.

## The rule going forward

`tests/test_curated_data.py` refuses an image that has neither a credit nor an
explicit `credit_status: "unconfirmed"`. That is deliberately not the same as
requiring a credit: it makes an unknown provenance a visible, recorded
decision rather than an empty string nobody notices.
